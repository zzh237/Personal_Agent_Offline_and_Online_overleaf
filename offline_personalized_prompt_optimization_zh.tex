\section{结论}

可以把原方案改成提示词版本，但不能把策略改成最终回答模型。原方案的主链必须保留：
\begin{equation}
  x
  \longrightarrow
  a\sim\policy(\cdot\mid x)
  \longrightarrow
  \FA.\operatorname{Execute}(a,x)
  \longrightarrow
  y_a.
  \label{eq:chain}
\end{equation}
策略仍然只决定如何执行。冻结的 FA 读取任务 \(x\) 和执行指令 \(a\)，再生成最终回答
\(y_a\)。

本版本只改两处：
\begin{itemize}
  \item \(a\) 不再是固定的三因子标签，而是一条自然语言执行指令；
  \item \(\mathcal A\) 不再是手写的 18 个动作，而是从真实用户纠正中得到、经执行验证的指令库。
\end{itemize}
因此不再需要 Compiler。除此之外，\(\Dhist,\Dtrain,\Dholdout,\Xholdout,
\Xsim,C,c,P_u,y_a,r_a,A_a,\policy,\basepolicy\)、FA 和 Judge 都保留原义。

提示词优化和提示词选择已有研究，不能声称``此前没有人做过提示词版本''。较窄、仍需实验
验证的差异是：\textbf{一个用户、冻结的黑盒 FA、由真实纠正形成的可查指令库、轻量策略
选择指令，以及同一套离线到在线 GRPO 更新。}

\section{为什么选择指令库}

提示词动作有三种直接做法：
\begin{itemize}
  \item \textbf{自由生成：}策略每次写一条新指令。表达力强，但容易加入用户从未说过的偏好，
    也很难审计。
  \item \textbf{适配器库：}策略选择一个参数适配器。它不再是提示词版本，也不适合只能通过
    API 调用的冻结 FA。
  \item \textbf{已验证指令库：}每条指令来自真实纠正，保存来源，并先经过 FA 和 Judge
    验证。策略只在这些指令中选择。
\end{itemize}

本文采用第三种。它最接近原来的离散动作策略，也保留了黑盒 FA 的边界。它只是一个候选
方法，不表示提示词一定优于参数适配器。

\section{提示词动作空间}

\subsection{一条动作是什么}

每条 \(a\in\mathcal A\) 是可以直接放进 FA system message 的短指令。例如，当前
OOCSO 诊断样本中的纠正是：
\begin{quote}
别整这些花里胡哨的格式啊，你就老老实实说人话重写一遍呗。
\end{quote}
可以从中提出候选指令：
\begin{quote}
使用普通中文短句；不要加粗、编号或小标题。
\end{quote}
后一句只有在回放原任务后确实改善回答，才进入 \(\mathcal A\)。指令必须描述执行方式，
不能泄露任务答案，也不能替代 FA 完成任务。

每条库记录至少包含：
\begin{center}
\small
\begin{tabularx}{0.94\textwidth}{@{}L{0.23\textwidth}Y@{}}
  \toprule
  字段 & 内容 \\
  \midrule
  \texttt{instruction} & 交给 FA 的指令文本，即动作 \(a\) \\
  \texttt{scope} & \texttt{global} 或适用的任务类别 \(c\) \\
  \texttt{evidence\_ids} & 支持这条指令的 \(\Dtrain\) 会话和轮次 \\
  \texttt{validation\_ids} & 已完成执行验证的训练任务 \\
  \texttt{status} & 只有 \texttt{validated} 才能进入策略候选集 \\
  \bottomrule
\end{tabularx}
\end{center}

指令库总是包含空动作 \(a_{\varnothing}\)。它不添加个性化指令，用来判断个性化是否真的
有帮助。

\subsection{从真实纠正建立动作}

只使用 \(\Dtrain\)：
\begin{enumerate}
  \item 找到用户明确要求修改，且修改后回答被接受的轮次。
  \item 冻结 FA 把用户原话整理成一条短执行指令。它只能删去题目内容和重复文字，不能补充
    新偏好。
  \item 在纠正前的任务 \(x\) 上运行空动作和候选动作，得到两个 FA 回答。
  \item Judge 读取同一段训练侧证据并比较两个回答。有确定性任务检查器时，Judge 也读取
    任务是否成功。
  \item 只有候选动作改善偏好且不破坏任务完成时，才标为 \texttt{validated}。
\end{enumerate}

空反馈、未闭合思考块导致的空文本、少于一个完整要求的 hint，以及纠正后仍不满意的记录
全部丢弃。当前数据里出现过只剩``和''的损坏 hint；它不能成为动作。

\subsection{当前任务的候选集}

每条指令在入库时已有适用范围。对类别为 \(c(x)\) 的任务，
\begin{equation}
  \mathcal A_x
  =
  \{a_{\varnothing}\}
  \cup
  \{a\in\mathcal A:
    \operatorname{scope}(a)=\texttt{global}
    \ \text{或}\ c(x)\in\operatorname{scope}(a)\}.
  \label{eq:candidates}
\end{equation}
首个实验直接枚举 \(\mathcal A_x\)。只有库变得很大后，才加入固定的检索上限。检索规则
必须在评测前锁定，不能读取 \(\Dholdout\)。

\section{策略模型}

\subsection{参数}

\(\policy\) 使用当前 OOCSO 已配置的
\texttt{Qwen/Qwen3-4B-Thinking-2507}。每位用户有一个 LoRA：
\[
  r=16,\qquad
  \alpha=32,\qquad
  \text{target}=
  \{\texttt{q\_proj},\texttt{k\_proj},
    \texttt{v\_proj},\texttt{o\_proj}\}.
\]
当前 \texttt{preview\_pi0\_student.pt} 有 288 个 LoRA 张量，共
\(11{,}796{,}480\) 个参数。该文件只能说明当前代码已经能保存适配器，不能证明本文算法
已实现。

\subsection{输入}

策略输入仍然只有 \(x\)。序列化格式固定为：
\begin{quote}
\texttt{[TASK\_STATE]}\par
当前 system message、用户任务、已经发生的工具返回和对话状态\par
\texttt{[/TASK\_STATE]}\par
\texttt{[EXECUTION\_INSTRUCTION]}
\end{quote}
评测第一次回答时，\(x\) 不包含当前任务尚未发生的用户纠正。用户偏好存于该用户的 LoRA
和已验证动作库中。\(P_u\) 不拼进策略输入。

\subsection{输出和候选打分}

输出是动作文本 \(a=(t_1,\ldots,t_{L_a})\)，不是回答。对每个
\(a\in\mathcal A_x\)，用 teacher forcing 计算长度归一化分数：
\begin{equation}
  s_{\theta}(a,x)
  =
  \frac{1}{L_a}
  \sum_{j=1}^{L_a}
  \log p_{\theta}
  \left(t_j\mid
    \operatorname{Serialize}(x),t_{<j}\right).
  \label{eq:sequence-score}
\end{equation}
空动作使用固定 token \texttt{<NO\_PERSONAL\_INSTRUCTION>} 参与打分，传给 FA 时再还原为
空字符串。候选上的策略分布为
\begin{equation}
  \policy(a\mid x)
  =
  \frac{\exp(s_{\theta}(a,x)/T)}
       {\sum_{a'\in\mathcal A_x}
        \exp(s_{\theta}(a',x)/T)}.
  \label{eq:policy}
\end{equation}
\(\basepolicy\) 使用同一公式和同一动作库，但关闭 LoRA。这样两条评测链只差训练过的
策略参数。

\section{离线算法}

\subsection{数据切分}

先按完整会话和时间把 \(\Dhist\) 切成 \(\Dtrain\) 和 \(\Dholdout\)。一个会话不能拆到
两边。任务类别 \(C\) 和比例在运行前固定。只有 \(\Dtrain\) 可以用于：
\begin{itemize}
  \item 建立 \(\mathcal A\)；
  \item 提取可选的 \(P_u\)；
  \item 构造 \(\Xsim\)；
  \item 给 Judge 提供偏好证据；
  \item 训练 \(\policy\)。
\end{itemize}
\(\Dholdout\) 和 \(\Xholdout\) 不得进入以上任何一步。

\subsection{执行与打分}

对每个 \(x\in\Xsim\)，枚举或从 \(\mathcal A_x\) 采样 \(K\) 条指令。每条指令都通过同一个
冻结 FA：
\begin{equation}
  y_a=\FA.\operatorname{Execute}(a,x).
  \label{eq:execute}
\end{equation}
这里没有 Compiler。动作文本 \(a\) 直接进入 FA。

Judge 读取训练侧真实证据、任务 \(x\)、回答 \(y_a\)，以及可选的冻结摘要 \(P_u\)：
\begin{equation}
  r_a
  =
  \Judge(\Dtrain,x,y_a;P_u).
  \label{eq:reward}
\end{equation}
对工具任务，确定性检查器的成功或失败也放进 Judge 输入。Judge 仍只输出一个固定范围的
标量 \(r_a\)。同一 \(x\) 下的所有回答必须使用同一个 Judge 提示和同一套 FA 参数。

\subsection{组相对优势}

\begin{equation}
  \bar r
  =
  \frac{1}{K}\sum_{a\in\mathcal A_x^{(K)}}r_a,
  \qquad
  A_a=r_a-\bar r.
  \label{eq:advantage}
\end{equation}
若所有动作得分相同，该组不产生梯度。不要为制造优势而改 Judge 分数。

\subsection{GRPO 更新}

收集动作时保存 \(\oldpolicy(a\mid x)\)。更新时计算
\begin{equation}
  \rho_a(\theta)
  =
  \frac{\policy(a\mid x)}
       {\oldpolicy(a\mid x)}.
\end{equation}
使用原方案的 clipped GRPO：
\begin{equation}
  \mathcal L_{\mathrm{GRPO}}(\theta)
  =
  -\mathbb E_x
  \left[
  \frac{1}{K}
  \sum_a
  \min\left(
    \rho_a A_a,\,
    \clip(\rho_a,1-\epsilon,1+\epsilon)A_a
  \right)
  \right]
  -\beta H\!\left(\policy(\cdot\mid x)\right).
  \label{eq:grpo}
\end{equation}
优化器只更新 LoRA 参数 \(\theta\)。FA 和 Judge 的 token 概率不进入损失。

\subsection{离线工作流}

\begin{enumerate}
  \item 切分 \(\Dhist\)，冻结 \(\Dholdout\) 和 \(\Xholdout\)。
  \item 从 \(\Dtrain\) 的真实纠正建立并验证 \(\mathcal A\)。
  \item 可选地从 \(\Dtrain\) 提取一次 \(P_u\)，随后冻结。
  \item 从训练侧任务构造 \(\Xsim\)，并过滤与 holdout 的近重复。
  \item 对每个 \(x\) 形成 \(\mathcal A_x\)，通过 FA 得到 \(y_a\)。
  \item Judge 给出 \(r_a\)，计算 \(A_a\)。
  \item 用式~\eqref{eq:grpo} 更新 \(\policy\)，得到离线策略 \(\pi_0\)。
\end{enumerate}

\section{在线算法}

部署从离线策略 \(\pi_0\) 和同一动作库开始。每次任务仍按式~\eqref{eq:chain} 执行。
在线数据分两类处理：
\begin{itemize}
  \item 用户满意或任务成功：保存该次 \((x,a,y_a,r_a)\)，用于后续组相对更新；
  \item 用户明确纠正：从用户原话提出一个新动作候选，但不能直接加入 \(\mathcal A\)。
\end{itemize}

新候选先经过三项检查：
\begin{enumerate}
  \item 它能指向当前在线纠正，且没有加入用户未表达的要求；
  \item 在当前任务上重新运行 FA 后，Judge 分数提高且任务仍成功；
  \item 在一小批已通过的训练侧回放任务上，不造成明显退化。
\end{enumerate}
通过后，候选成为 \(\mathcal A\) 的新记录。然后在包含新动作、当前动作、空动作和若干旧动作
的组内重新执行、打分，并继续使用式~\eqref{eq:grpo}。在线阶段没有第二套训练目标。
\(\Dholdout\) 和 \(\Xholdout\) 始终不可见。

\section{推理}

对新任务 \(x\)：
\begin{enumerate}
  \item 按式~\eqref{eq:candidates} 得到 \(\mathcal A_x\)；
  \item 按式~\eqref{eq:policy} 计算动作分布；
  \item 评测时取 \(a^\star=\arg\max_a\policy(a\mid x)\)，交互时也可采样；
  \item 运行 \(y_{a^\star}=\FA.\operatorname{Execute}(a^\star,x)\)；
  \item 返回 \(y_{a^\star}\)。
\end{enumerate}

默认不把 \(P_u\) 再拼进 FA。这样可把效果归因于动作策略，而不是额外的完整用户画像提示。
\(P_u\) 仍可作为单独基线。

\section{当前代码与本文算法的关系}

现有 \path{oocso/pref/run_pref.py} 让 Qwen3-4B 直接生成回答，再用 GRPO/OPD 更新回答
token。本文不是那条代码路径。本文的 \(\policy\) 只给候选执行指令打分，最终回答由 FA
生成。

若开始实现，应放在新的 \path{pref_prompt_action_grpo/} 目录，复用以下通用部分：
\begin{itemize}
  \item \path{config.py} 的模型名和 LoRA 参数；
  \item \path{env/} 的工具执行与成功检查；
  \item \path{pref/pref_prm.py} 的冻结 Judge 接口；
  \item \path{models.py} 的 teacher-forcing log-prob 计算。
\end{itemize}
不要修改现有直接回答实验，避免两种架构混在一起。

\subsection{报告}

对真实 \(\Xholdout\)，比较训练策略与基础策略在同一 FA 下的回答。按类别报告：
\begin{align}
  \operatorname{Acc}_c
  &=
  \frac{1}{N_c}
  \sum_{x\in\Xholdout^{(c)}}
  \mathbf 1[y_{\theta}\succ y_{\mathrm{base}}],\\
  \operatorname{Acc}_{\mathrm{macro}}
  &=
  \frac{1}{|C|}
  \sum_c\operatorname{Acc}_c,\\
  \operatorname{Acc}_{\mathrm{micro}}
  &=
  \frac{1}{N}
  \sum_c N_c\operatorname{Acc}_c.
\end{align}
另外单独报告任务成功率、第一次回答符合偏好的比例、动作库大小、动作长度、FA 调用次数和
在线新增动作数。不要把个性化和任务成功压成一个分数。

\section{已有工作与创新边界}

以下方向已有直接工作：
\begin{itemize}
  \item DSO 从日志反馈学习按上下文选择提示词；
  \item AGP 自动改写个性化推荐中的画像提示词；
  \item GEPA 根据执行轨迹和文字反馈迭代提示词；
  \item OPPU 为每位用户训练独立的参数高效适配器。
\end{itemize}
因此，``提示词个性化''、``冻结模型后优化提示词''和``根据反馈改写提示词''都不是新的。
本文可能不同的是完整组合，而不是任何一个单独部件。正式写成论文贡献前，还需要更完整的
文献检索和直接对照实验。

\section{最小可行实验}

当前数据只够做流程验证：
\begin{enumerate}
  \item 从现有三条有效纠正中提取候选动作，并确认损坏 hint 被拒绝。
  \item 在 80 个离线工具任务上比较空动作和已验证动作。
  \item 训练一个新的提示词动作 LoRA，不复用当前直接回答检查点作为结果。
  \item 用 30 个 dev 任务检查任务成功是否下降。
  \item 暂不对 30 个 eval 任务报告正式个性化结论。
\end{enumerate}

正式实验还需要一位真实用户的完整历史，以及按时间保留的未来问题。没有这两项时，可以证明
代码能运行，但不能证明离线个性化或在线适应有效。

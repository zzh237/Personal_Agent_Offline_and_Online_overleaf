\subsection{Local Extractor Prompt}

\begin{PromptBox}[Local Personal Card extractor]
\lstinputlisting[style=prompt]{appendix/extractor_prompt_en.txt}
\end{PromptBox}

The user message is the observation serialized as sorted JSON. The model must
return one JSON object. The validator then checks all enums, numeric ranges,
length limits, evidence type, and the fixed \texttt{local\_only} privacy value.

\subsection{Claude CLI Executor Prompt}

\begin{PromptBox}[Frozen executor system and user template]
\lstinputlisting[style=prompt]{appendix/executor_prompt.txt}
\end{PromptBox}

The profile condition appends the rendered profile to the system prompt. The
baseline uses the same system prompt without the profile. Both receive the same
user template and current task.

\subsection{Claude CLI Invocation}

\begin{PromptBox}[Command used for executor and judge calls]
\lstinputlisting[style=prompt]{appendix/claude_cli_command.txt}
\end{PromptBox}

All 32 remote calls use this adapter and the same Sonnet 4.5 model through
Amazon Bedrock. Baseline and profile answers run in separate processes. The
judge also starts fresh for each answer order. The recorded envelopes report
one or two turns, no web-search requests, and no permission denials.

\subsection{Pairwise Judge Prompt}

\begin{PromptBox}[Order-swapped pairwise judge]
\lstinputlisting[style=prompt]{appendix/judge_prompt.txt}
\end{PromptBox}

The judge returns \texttt{winner} in
\{\texttt{A}, \texttt{B}, \texttt{tie}\}, four integer scores from 1 to 5, and
a short reason. We run the same comparison again with the answers swapped. A
pair is position-consistent only when both calls select the same underlying
answer.

\subsection{Rendered Profile Example}

The following profile was used in the repeated-support run for a knowledge
explanation task. It is an English rendering of the JSON sent to the executor.

\begin{PromptBox}[Compact profile sent with the current task]
\begin{lstlisting}[style=prompt]
{
  "task_type": "knowledge explanation",
  "preferences": [{
    "instruction": "Give concrete steps and essential details; check key
      facts and calculations; state uncertainty; follow explicit keep,
      delete, and prohibition conditions.",
    "feedback_types": [
      "constraint_adherence", "correctness", "detail_depth",
      "format_structure", "verbosity"
    ],
    "support": 4,
    "confidence": 0.880,
    "mean_likert": 2.00,
    "scope": "task_type"
  }],
  "policy": "Apply only relevant preferences. The current request
    overrides the profile."
}
\end{lstlisting}
\end{PromptBox}

The remote request does not contain source conversation IDs, source hashes,
old tasks, old answers, corrections, or card evidence strings.
